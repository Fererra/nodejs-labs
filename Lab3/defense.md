## Наша частина — Task №5: Генерація тестових даних

Файл `src/data/transactions.json` — масив з 5 записів:

| Поле | Тип | Опис | Приклад |
|------|-----|------|---------|
| `id` | number | Унікальний ідентифікатор | `3` |
| `type` | string | `"income"` або `"expense"` | `"expense"` |
| `amount` | number | Сума в грн | `300` |
| `purchase` | string | Опис покупки | `"Кава та круасан"` |
| `category` | string | Категорія | `"Розваги"` |
| `date` | string | Дата `YYYY-MM-DD` | `"2026-03-17"` |

Дані підібрані для демонстрації фільтрів: 2 типи, 5 категорій, 2 місяці, суми від 150 до 20000.

### Як дані використовуються

Репозиторій читає файл **4-ма способами** (суть лаби):

1. **Sync** (`getAll`) — `fs.readFileSync()` — блокує Event Loop
2. **Callback** (`getById`) — `fs.readFile(path, callback)` — результат через функцію зворотного виклику
3. **Promise** (`save`) — `fs.readFile(path).then().catch()` — ланцюжок
4. **async/await** (`update`, `delete`) — `await fs.readFile(path)` — найчитабельніший

Сервіс фільтрує дані **в пам'яті** через `.filter()`.

## Контрольні питання

### 1. Що таке архітектура «клієнт-сервер»?

Модель, де **клієнт** (браузер) надсилає запити, а **сервер** (Express) обробляє і повертає відповідь. Спілкуються по HTTP.

### 2. Різниця між HTML та HTTP?

- **HTML** — мова розмітки (що показувати)
- **HTTP** — протокол передачі (як передавати)

### 3. Різниця між HTTP та HTTPS?

HTTPS = HTTP + TLS-шифрування. HTTP (порт 80) — дані відкритим текстом. HTTPS (порт 443) — дані зашифровані, потрібен SSL-сертифікат.

### 4. Відмінності GET та POST?

| | GET | POST |
|---|-----|------|
| Призначення | Отримати | Створити/надіслати |
| Параметри | В URL | В body |
| Кешування | Так | Ні |
| Ідемпотентність | Так | Ні |

### 5. Заголовки HTTP та кукі?

**Заголовки** — метадані запиту/відповіді (`Content-Type`, `Authorization`). **Кукі** — дані, що сервер надсилає через заголовок `Set-Cookie`, клієнт зберігає і повертає в `Cookie`. Використання: сесії, авторизація.

### 6. Коди стану HTTP?

| Діапазон | Значення | Приклади |
|----------|----------|----------|
| 2xx | Успіх | 200 OK, 201 Created |
| 3xx | Перенаправлення | 301, 302 |
| 4xx | Помилка клієнта | 400, 404 |
| 5xx | Помилка сервера | 500 |

### 7. Що таке порт TCP?

Числовий ідентифікатор (0–65535), що визначає сервіс на комп'ютері. 80 — HTTP, 443 — HTTPS, 3000 — наш Express. Аналогія: IP — адреса будинку, порт — номер квартири.

### 8. Для чого Express?

Спрощує маршрутизацію, middleware, парсинг body, шаблонізацію, роздачу статичних файлів. Без нього — ручний парсинг URL, headers, body.

### 9. Що таке Middleware?

Функції з доступом до `req`, `res`, `next()`, що виконуються послідовно. Можуть змінювати запит, завершувати відповідь або передавати далі.

```javascript
app.use(express.json());
app.use(express.urlencoded({ extended: true }));
app.use("/", indexRouter);
```

### 10. Маршрутизація та маршрутизатори?

**Routing** — визначення реакції на URL + HTTP-метод. **Router** — модуль для групування маршрутів, підключається через `app.use()`.

### 11. Чим роутер відрізняється від контролера?

Router визначає **куди** → який обробник. Controller визначає **що** робити з запитом (валідація, виклик сервісу, формування відповіді).

### 12. Шаблон MVC?

- **Model** — дані та логіка (Transaction, Service, Repository)
- **View** — відображення (EJS-шаблони)
- **Controller** — посередник (приймає запит → Model → View)

### 13. Шаблонізатори?

Генерують HTML на сервері з динамічними даними. EJS: `<%= value %>` — вставка з екрануванням, `<%- include() %>` — включення, `<% if() {} %>` — логіка.

### 14. XSS-атака?

Впровадження JS-коду через введення (`<script>alert('hack')</script>`). Захист: EJS `<%= %>` автоматично екранує HTML, валідація на сервері.

### 15. Для чого package.json?

Маніфест проєкту: залежності, скрипти, тип модулів (`"type": "module"`), точка входу. `npm install` встановлює залежності з нього.

### 16. Що таке модулі?

Окремі файли коду. **CommonJS**: `require/module.exports`. **ESM**: `import/export`. Наш проєкт — ESM.

### 17. Синхронний vs асинхронний I/O?

**Sync**: простий код, але блокує Event Loop. **Async**: не блокує, але складніший код. Для сервера завжди краще async — Node.js однопоточний.

### 18. Callback функція?

Функція-аргумент, що викликається після завершення операції. Паттерн Node.js: `(error, data) => {}` — перший аргумент помилка.

### 19. Callback hell?

Вкладені callbacks → «піраміда» нечитабельного коду. Рішення: Promises, async/await.

### 20. Для чого проміси?

Promise — об'єкт майбутнього результату. Стани: pending → fulfilled/rejected. Ланцюжок `.then().catch()` замість вкладеності callbacks.

### 21. Спільне між промісами та async/await?

`async/await` — синтаксичний цукор над Promises. Обидва працюють з Promise-об'єктами, не блокують Event Loop. `async` функція завжди повертає Promise.

### 22. Обробка помилок?

- **Callbacks**: `if (error) { ... }` — перевірка першого аргументу
- **Promises**: `.catch(err => ...)`
- **async/await**: `try { ... } catch (error) { ... }`

### 23. Чиста архітектура?

Залежності спрямовані всередину: зовнішні шари (Controllers) → середні (Services) → внутрішні (Entities). Бізнес-логіка не залежить від фреймворків і БД.

### 24. IoC, DIP, DI?

**IoC** — управління передається зовні (Express викликає наші контролери). **DIP** — залежність від абстракцій (сервіс залежить від інтерфейсу репозиторію, а не реалізації). **DI** — залежності передаються через конструктор:

```javascript
const service = new FinanceService(repository);     // ← DI
const controller = new FinanceController(service);  // ← DI
```
